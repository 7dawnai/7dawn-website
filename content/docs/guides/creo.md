# Creo

3Studio 可以连接你电脑上已安装的 **Creo**（PTC 的参数化 CAD 软件），让 Agent 直接替你读写模型参数、重新生成模型、查询质量属性和装配清单、导出文件——而不用你自己在 Creo 里手动点。

> ⚠️ **仅支持 Windows，且需要一次性的前置安装步骤（见下文）。** 通用的 Python 环境设置见《[概览与通用设置](./cae-overview.md)》——本页写 Creo 特有的安装与配置部分。

## 安装 Creoson

Creo 本身不提供能直接被外部程序调用的接口，3Studio 通过一个叫 **Creoson**（基于 Creo 自带的 J-Link 接口的本地服务）来驱动 Creo。使用前需要先完成一次性安装——3Studio 已知可用范围是 Creo 7–12。

### 一键安装（推荐）

打开**设置 → 工具**标签页，往下滚动能看到 **Creo** 卡片。如果 Creoson 还没装，卡片上会提示"Creoson 未安装"，点旁边的**「安装 Creoson」**按钮，按向导走完即可。

安装包已内置 Creoson（约 60MB，含独立 Java 运行环境，无需你另装 Java）：点击「安装 Creoson」即从本地安装，**不需要联网**。仅当你使用的构建不含内置包时，才会回落到联网下载官方安装包。

1. **选安装路径**：默认会填好一个 3Studio 管理的目录，一般不需要改；也可以点"浏览…"换一个位置。
2. **确认 Creo 安装目录**：3Studio 会自动扫描本机所有盘符找到已装的 Creo，把找到的版本列成候选项供你选择；如果没扫到（比如装在了不常见的位置），点"手动指定 Creo 安装目录"，选中 Creo 的安装根目录。
3. 点**「开始安装」**：内置包走本地复制，会显示"解压 → 生成配置"两阶段进度；只有回落到联网下载时才会多一个"下载"阶段，显示"下载 → 解压 → 生成配置"三阶段进度。完成后状态行会显示「Creoson 3.0.1 · 安装目录」，下方的 Creoson 目录、端口、Creo 启动目录三项设置也会被自动填好——不需要你自己手建任何文件。

内置与联网下载用的都是 Creoson 官方 3.0.1 版本的发布包，自带的 JRE（Java 运行环境）已支持 Creo 12，不用你单独装 Java。**仅当你使用的构建不含内置包、回落到联网下载时**才用得到下面这项：如果这台电脑访问 GitHub 不方便，可以在端口输入框下方的**「下载地址（高级）」**里填一个你能访问到的镜像地址再重新点安装——但这个镜像**必须是官方 3.0.1 安装包的字节级一致副本**（3Studio 会校验 sha256 完整性，版本不同或内容被改动过的镜像会被直接拒绝，安装失败）。

**下载失败怎么办？**（仅回落到联网下载这条路径时才可能遇到，比如断网、地址填错、校验不通过）3Studio 会显示明确的错误信息，并且**不会改动你已有的任何配置**——已经配置好的部分不会被清空，可以换个安装路径或下载地址重试，或者改用下面的手动安装。

### 手动安装（备选）

如果一键安装走不通（比如网络限制无法自动下载），也可以完全手动完成：

1. 下载并运行官方的 **CreosonSetup** 安装向导，安装时指向你机器上的 Creo 安装目录（用较新的 Creoson 分发包——如 3.0.1 WithSetup）。
2. 启动 Creoson 服务的脚本是随分发包自带的 **`creoson_run.bat`**；运行 CreosonSetup 并指向 Creo 后，它会在同一目录生成 **`setvars.bat`**（记录 Creo 路径与端口）。**注意**：拉起 Creo 桌面程序用的 **`nitro_proe_remote.bat` 不是 CreosonSetup 自动生成的**（一键安装会自动帮你代生成这个文件；手动路线下需要你在同一目录自己创建——Creoson 出于安全要求固定用这个文件名），内容为调用你 Creo 安装里的 `parametric.bat` 来启动 Creo GUI。记下这个文件夹——待会要填进 3Studio 的设置里。
3. **重要**：CreosonSetup 同一目录下通常还会有一份 Creo 的 `config.pro`（Creo 的配置文件）。PTC 官方文档明确提示：如果 Creo 启动时弹出欢迎 / 起始页这类弹窗，而 3Studio 这边又在反复重试拉起 Creo，可能会导致 Creo 崩溃。请在首次使用前打开这份 `config.pro`，确认已经加上抑制启动弹窗的设置（常见做法是关闭"起始页 / Getting Started"欢迎界面这一项；具体选项名请以 Creoson 官方安装说明或你所用 Creo 版本的帮助文档为准，不同版本用词可能略有差异）。遇到 Creo 反复启动失败或崩溃，请优先回来检查这一步。

完成手动安装后，去下面"配置 Creo"一节，把三项路径 / 端口手动填进 3Studio。

## 配置 Creo

如果是走的一键安装，下面三项已经自动填好，可以跳过本节；如果是手动安装，需要手动填三项：

- **Creoson 目录**：包含 `creoson_run.bat` 的那个文件夹，点"浏览…"选择。
- **Creoson 端口**：Creoson 服务监听的端口号，默认 `9056`，一般不需要改。**必须与 `setvars.bat` 里的 `JSON_PORT` 一致**（那才是 Creoson 服务端真正监听的端口）——两者不一致会连不上。一键安装生成的 `setvars.bat` 由 3Studio 管理：在这里改端口会自动同步改写这份文件的 `JSON_PORT`，不用你手动去改；但**手动安装**的 `setvars.bat` 不受 3Studio 管理，改这里的端口不会自动同步过去，需要你自己打开文件对齐。
- **Creo 启动目录**：`nitro_proe_remote.bat` 所在的文件夹（一键安装时跟 Creoson 目录相同）。

**测试连接**：点击"测试连接"按钮，3Studio 会分别检查两层是否可达：**Sidecar**（3Studio 自己的后台桥接进程）与 **Creoson**（真正驱动 Creo 的那个本地服务），两者分开显示状态，能准确定位到底是哪一层出的问题——比如 Creoson 端口填错时，Sidecar 会显示正常但 Creoson 会显示不可达，一眼能看出问题所在。注意一点：Creoson 服务是在你**第一次启动 Creo 会话**时才被拉起的——刚装完、还没让 agent 打开过任何模型就点测试连接，Creoson 显示不可达属于正常现象，不代表安装失败；先跑一次会话再测即可。会话停止后同理——停止会话会一并回收 Creoson，此时测试连接显示 Creoson 不可达是预期状态，重新启动会话即恢复。

**重启 Bridge**：改了上面三项配置、或桥接进程卡住时，点这个按钮手动重启 Creo 桥接进程，不需要重启整个应用。重启只回收 **Creoson** 后台进程（驱动 Creo 的那个 Java 服务本身），不会残留占端口的 Creoson 孤儿进程——**你的 Creo 窗口不受影响，不会被一并关掉**。之后重新启动会话，3Studio 会自动连回这个仍然开着的 Creo。

**查看日志**：点击展开桥接进程最近的日志内容，排查连接问题时可以先看这里。

**状态标签与 Creo 安装检测**：卡片标题旁的标签会反映 3Studio 是否找到了一份有效的 Creo 安装——未检测到（灰）、失效（红，指向的安装现在校验不通过，可点"清除"）、检测异常（金）、出错（红）、桥未运行（金，环境已就绪但桥接进程还没启动）、就绪（绿）。点"检测"可以重新扫描；如果没扫到（比如装在了不常见的位置），点"手动添加…"选中 Creo 的安装根目录。这跟上面"确认 Creo 安装目录"里一键安装向导内的检测是两回事——那个只在装 Creoson 时用一次，这里是卡片长期显示的连接状态。

> Creo 也参与设置页顶部通用的 **Python 环境** 卡片（基座 Python + 隔离环境根目录，见《[概览与通用设置](./cae-overview.md)》），兼容范围是 Python 3.9–3.13。跟 STK / Ansys 不同，Creo 卡片本身**没有**"手动指定 Python 解释器"这一项——它总是自动用当前生效的基座 Python 搭建隔离环境。但卡片上有一个"重建隔离环境"按钮：如果这个隔离环境本身出了问题（比如依赖安装不完整、解释器损坏），点这个按钮可以删掉重建，不需要手动干预文件系统；如果 Bridge 正在运行，3Studio 会先自动停掉 Bridge 再重建，重建完成后会自动恢复运行，不需要你手动干预。

## 连接状态

跟 STK 一样，**Creo 没有侧边栏"运行时"面板里的状态徽标**——连接状态只能在设置页面的这张 Creo 卡片里查看，不会出现在侧边栏底部的"运行时"面板中。

## 并发与超时行为

**同一时刻只有一个 Creo 请求真正在线上**：同一个工作区里的 Creo 调用逐个执行，这个约束由 3Studio 自己保证，不再依赖调用方自律。**但转入后台的长任务不占用这个队列**——重新生成、导出这类长操作转入后台轮询之后，它完成前你仍可以让 Agent 发起别的 Creo 调用，两者会在更底层交错。这类交错发起的调用有时会等不到通道空出来，Agent 会看到一条"通道正忙"的提示——跟下面"没回话"那条提示是**相反**的两件事：这种情况下调用**根本没有发出去**，Creo 那边什么都没发生，重试（包括写操作）是安全的，不需要特别处理，等一下再让 Agent 重试即可。**跨工作区同样不排队**——两个工作区同时用 Creo 时，双方的请求会交错打到同一个 Creo 会话上，可能互相踩到对方正在操作的模型。请不要在多个工作区里同时驱动 Creo。

**"没回话"不等于操作失败**：Agent 交互类调用（比如读写参数、查尺寸、查材料与单位）最多等 60 秒；**保存**这类同步长任务调用最多等 8 分钟；**重新生成**、**导出**转入后台轮询执行，Creo 内部单次操作最多等 30 分钟——但这类工具调用本身很快返回、不会占住 Agent 这次调用，完成前你仍可以让 Agent 发起别的 Creo 请求（参见上一条"排队"的说明）。超过各自的等待时间后，Agent 会看到一条"没有证据表明引擎已死"的提示。此时那次操作**可能仍在 Creo 内部进行**，效果未知——**不要让 Agent 在这种情况下重试写操作**（比如改参数、保存），否则同一次修改可能被应用两遍。正确做法是让 Agent 先查一下会话状态，或者干脆结束这次会话。

## 让 Agent 使用 Creo

> **推荐搭配「结构专家」Agent**：新建 Agent 时选择「结构专家」模板，它内置了 Creo 几何技能，同时内置 HyperMesh 建模技能与 Nastran 求解技能——从打开装配、改参数、重新生成到导出几何，再到网格划分与求解，可以交给同一个 Agent 连着做。Creo 侧交接给 HyperMesh 的是导出的 STEP 文件。下文能力均以结构专家为准。

配置好之后，你可以在对话里直接让 Agent 操作 Creo：

- **启动 / 停止会话**：Agent 第一次用到 Creo 时会自动拉起 Creoson 和 Creo 桌面程序（约 10–30 秒，期间 Creo 窗口会变为可见）；用完之后也可以让 Agent 停止会话。
- **打开模型**：打开一个零件 / 装配 / 工程图文件并使其成为当前激活的模型；如果打开时触发了重新生成，Agent 会一并报告是否出错。需要丢弃当前会话里的模型状态、从磁盘重新加载时，可以让 Agent 用「强制重载」方式打开；重载后 Agent 会自动复查几何，复查不过会改走「重启 Creo 会话」彻底恢复。
- **读写参数与尺寸**：读取 Creo 参数、模型尺寸，或某个族表实例的行数据和表头；反过来修改某个参数或尺寸的值。
- **重新生成模型**：改完参数或尺寸后，让 Agent 重新计算模型。
- **查询质量属性**：读取质量、体积、表面积、惯量张量和质心坐标（默认坐标系下的三轴坐标）。会一并返回该模型当前使用的单位系统（长度单位、质量单位）——同一个质量数值在不同单位系统下可以相差好几个数量级，读不到单位系统时会明确告警，此时数值不要直接拿去跨软件接力使用。
- **设定与查询材料**：Agent 可以给零件设材料并当场回读核对，同时算出隐含密度，避免材料没设上却一路算下去。设材料时也会一并给出单位系统，隐含密度这类量纲量同样受单位影响。
- **读写关系式**：Agent 写关系式时会自动与模型里已有的合并（不会覆盖），写完回读并核对每个符号在模型里解得出来；解不出来会明确告警，因为 Creo 自己对这种错误完全不报。
- **读取装配清单（BOM）**：读取一个装配的组件树和每个组件的出现次数，可选带上每个实例的空间位置信息。
- **导出模型**：导出为 STEP / IGES / DXF / NEUTRAL / VRML / PDF / 3D PDF / PLOT 等格式，产物会保存到你的工作区文件夹里。产物会被校验（文件确实写出、非空、STEP 会核对是否真是 STEP 格式），导不出来会明确报错，不会静默返回成功。其中 3D PDF 这条格式还没有在真实 Creo 环境里跑通过一次导出，遇到问题欢迎反馈。
- **截图**：对当前模型视图截一张 PNG 图片（**需要机器上有可用的硬件加速 / GPU**——没有硬件加速的机器，比如很多云端 Windows Server，Creo 内部截不出图，这时会明确报错而不是卡住，属环境限制，参考本页"能干什么、不能干什么"一节）。
- **生成工程图**：让 Agent 一键生成套用了标准视图的工程图——Creo 自带可用的图纸模板，通常不需要你准备；具体见下面"工程图模板"一节。
- **工程图导出 PDF**：按工程图自身的图纸设置导出 PDF，默认导出全部图页，也可以只导出当前页或指定页码范围。产物同样会被校验，导不出来会明确报错，不会静默返回成功。
- **读写 Pro/PROGRAM**：读取或修改模型的条件特征（`IF` 判断块控制特征是否生效）、关系式、装配里哪些组件被纳入——常用于驱动同一模型的不同变体。Agent 会把导出的 Program 清单整理成结构化摘要（每个特征/组件带稳定编号和触发条件）方便编辑，写回前会自动核对版本号，版本落后会被 Creo 挡住而不是悄悄套用旧内容。
- **新建装配**：从 Creo 自带的空装配模板起手创建一个新装配，不需要你先手工准备一个空装配文件。
- **保存并验收产物**：把模型存到磁盘，并给出证据——默认核对 Creo 实际写出的那个版本文件（路径、字节数、时间戳）；交付节点可以要求更强的一档，把模型从会话里清掉再从磁盘读回来算一次质量属性，这是唯一能识破「文件能打开但组件其实取不回来」的检查。任何一档没通过都会明确报错，不会静默返回成功。**注意更强的那一档影响范围不止被验收的这个模型**：它会把当前 Creo 会话里所有"没有在窗口里显示出来"的模型一起从会话中清掉（真机实测：同一会话里另外两个未显示的装配被一并清空）——磁盘上的文件不受影响，但你需要重新打开它们才能继续用。如果这次会话里同时开着好几个模型，用这一档前请三思，或者先把要保留的模型显示出来再验收。
- **装配组件**：把一个零件放进装配里，两种放置方式二选一（不能同时用）：用坐标系（csys）约束定位——这是目前唯一完整支持、并在真实设备上验证过的约束方式；或者用「打包放置」配合一个位移，把同一个零件的多个实例摆到不同位置——csys 约束只能复用零件自带的那几个坐标系，做不到这件事，打包放置是唯一途径。**装配好的组件只存在于当前 Creo 会话里**，需要显式让 Agent 保存这个装配才会真正落盘，否则磁盘上的文件跟没装配前一样，改动会在会话停止或崩溃后丢失。
- **执行底层 Creoson 命令**：以上覆盖不了的操作（比如工程图标注、族表列操作、图层、视图切换等），Agent 可以直接执行一条底层 Creoson 命令；这条通道不是沙箱——命令会直接在你的 Creo 会话里对磁盘上的真实文件生效，没有回滚也没有预演。3Studio 只拦下一小份危险命令（比如删除文件、清空 PDM/产品数据管理工作区），其余全部原样转发；在「询问」模式下，这类调用会先弹一张审批卡等你确认后才真正执行。

有些操作需要你在 Creo 窗口里**手动交互**——比如让 Agent 请求你在屏幕上点选一个尺寸或坐标系，Agent 会先告诉你接下来要点什么，再等你在弹出的 Creo 窗口里完成点选，随后继续往下走。

## 工程图模板

Creo 里有两类看起来相似、但对生成工程图来说完全不同的文件：

- **format（`.frm`）**：只是一个图框——标题栏、边框这类版式元素，**不含任何视图布局信息**。用它生成工程图，Agent 拿不到"该摆几个视图、摆在哪"的指令。
- **template（`.drw`）**：图框 + 一组 **Template Views**（模板自带的视图布局指令），Creo 打开时会照着这些指令自动摆好标准视图（比如三视图 + 等轴测）。Agent 生成工程图必须用这一类文件。

**你通常不需要自己准备模板**——Creo 自带一批含 Template Views、可以直接用的 `.drw` 模板（在 Creo 安装目录下的 `Common Files/templates`，比如 `a3_drawing.drw`），Agent 会把其中一份拷贝到 Creo 的工作目录下，用不带路径的文件名调用。只有当自带模板确实满足不了你的图纸要求（比如需要套用你们公司自己的标题栏）时，才需要你准备一份自己的 `.drw` 模板，然后：

- 放在 Creo 的工作目录下，让 Agent 只填文件名；或者
- 直接告诉 Agent 模板的完整路径。

如果提供的文件不是含 Template Views 的 `.drw`（比如误传了一个 `.frm` 格式文件），工具会明确报错，并在错误信息里指向 Creo 自带的模板目录，不会静默生成一份没有视图的空白图纸。

## 能干什么、不能干什么

Creo 集成目前有以下明确的能力边界，是当前版本的既定限制，不是缺失或 bug：

- **不能创建新特征**（比如拉伸、旋转这类建模操作）。Agent 能修改、删除、抑制或恢复已经存在的特征，但不能凭空建一个新特征。
- **没有干涉 / 碰撞分析**能力。几何读取只能拿到包围盒和曲面 / 边的列表，判断两个零件是否碰撞干涉需要你自己在 Creo 里检查。
- **模型重新生成失败时**，Agent 能看到 Creo 自己报的原话（具体是哪一步、哪个原因导致的失败）和一份没能再生成的特征清单，不再只是笼统的"出错了"。此外，"没出错"也不代表几何一定有效——个别极端参数值（如负尺寸）会让模型悄悄进入无效状态。为此，Agent 在每次重新生成后会自动做一次几何合理性检查，结果分五种：正常；体积为负（几何损坏）；体积和质量都为零（多半是条件特征/抑制主动清空了模型，不算损坏）；有体积但没有质量（多半是没配材料）；检查本身跑不出结果（不能当作"健康"处理）。检查异常时 Agent 会按情况尝试"强制重载"从磁盘恢复干净副本——恢复是否成功以重载后的几何复查为准，复查仍异常时 Agent 会改走"重启 Creo 会话"来彻底恢复。特征级出错时 Agent 仍会自动截图给你看当时的状态。
- **截图依赖真实硬件加速**：没有 GPU / 硬件加速的机器（比如部分云端 Windows Server）无法截图，会返回明确的错误提示，属于环境限制，不是 3Studio 的 bug；这类机器上仍可正常读写参数、重新生成模型、查询质量属性等其他能力。
- 极少数不常用的底层命令尚未在真实设备上逐条验证过，行为可能与预期有出入；遇到异常结果可以直接反馈。
- Agent 的万能命令通道（逃生舱）**不是沙箱**：命令直接在你的 Creo 会话里对磁盘上的真实文件执行，没有回滚也没有预演。3Studio 只拦一小份危险命令名单，其余原样转发；在「询问」模式下这类调用会先弹审批卡等你确认。

## 常见问题

**什么情况下你的 Creo 会被关掉？** 只有一种情况会关掉你的 Creo：你让 Agent 主动结束这次 Creo 会话，而且只关掉这次会话自己拉起的那一个。**关闭 3Studio、点"重启 Bridge"、或者桥接进程自己崩溃，这三种情况都不会关掉你的 Creo**——Creo 窗口会继续留在桌面上，里面未保存的改动不受影响。

**复用已经开着的 Creo**：启动会话时，如果电脑上已经有一个 Creo 开着（不管是你自己手动打开的，还是上一轮会话留下的），3Studio 会直接连上这一个，不会另外再拉起一个新的；这种情况下结束会话时也**不会**把它关掉——3Studio 只关自己亲手拉起的那一个。

**约束**：同时开着两个及以上 Creo 时，3Studio 无法启动会话（见下文"Creo 一直启动失败……"一节），需要先手动关到只剩一个（或者一个都不留，让 3Studio 自己拉起）。

**测试连接失败，或 Agent 说连不上 Creo？** 先看"测试连接"分开显示的 Sidecar / Creoson 两个状态：如果 Sidecar 正常但 Creoson 不可达，多半是 Creoson 目录 / 端口填错了，或者这台电脑上另一个程序占用了对应端口，或者本地防火墙 / 安全软件拦截了 Creoson 这个本地进程；确认后点"重启 Bridge"再试一次，或点"查看日志"看具体报错。

**Creo 一直启动失败、或启动后不久就崩溃？** 回头检查本页"安装 Creoson"一节里提到的 `config.pro` 抑制启动弹窗设置是否生效——这是 PTC 官方文档里明确提到的已知风险。另外看一下电脑上是不是同时开着**两个或更多** Creo：驱动 Creo 的 Creoson 只有在恰好一个 Creo 在跑时才能连上，两个及以上时 3Studio 无法启动会话。（只开着一个 Creo 不受影响——3Studio 会直接连上它，这是受支持的正常路径。）关掉多余的几个、只留一个（或者一个都不留，让 3Studio 自己拉起），再让 Agent 重试。

**崩溃后 Agent 说"不可自愈"、不再自动重启了？** 这是预期行为，不是 bug，现在有两种情形会走到这一步。**情形一**：3Studio 崩溃后会先判断驱动 Creo 的 Creoson 服务本身是否还活着——**Creoson 还活着时才会自动重启几次；如果 Creoson 自己都没能挺过这次崩溃，3Studio 不会尝试任何自动重启**，直接明确告诉 Agent（进而告诉你）当前不可自愈。**崩溃后 Creo 仍然开着是有意的**——3Studio 刻意不去碰它，好让你未保存的工作留在里面；等你修好问题、重新启动会话，会自动连回这个仍然开着的 Creo，不需要你手动做什么。**只有当同时存在两个及以上 Creo 时**才需要你插手：这种情况下报告会给出进程清单和一条清理命令，关到只剩一个，再让 Agent 重新启动会话。（注意：**一个 Creo 会话在任务管理器里是两个进程**——`parametric.exe` 和 `xtop.exe`，所以那份清单里有两条并不代表开了两个 Creo；按窗口数、不要按进程数去数。）（这跟"3Studio 会不会主动关掉你正在用的 Creo 会话"是另一件事，参见上面"什么情况下你的 Creo 会被关掉"那条，两者不矛盾。）**情形二**：即便 Creoson 每次都还活着、每次都按情形一自动重启成功，**10 分钟内如果连续崩溃了 3 次，3Studio 也会主动停止自动重启**——反复重启进同一个故障没有意义。同样，只有存在两个及以上 Creo 时才需要按情形一的说明手动处理。你需要先排查并解决反复崩溃的根本原因（比如某个操作本身有问题、Creo 版本兼容性问题等），然后让 Agent 重新启动一次会话（`creo_session start`）——重新启动**成功**之后，崩溃计数会清零，重新开始计。
