# 支持的 CAE/CAD 软件：概览与通用设置

3Studio 可以连接你电脑上已经安装的专业工程软件，让 Agent 直接替你执行脚本、建模、仿真、计算这些工作，而不用你自己在这些软件里手动点。当前支持六款：

| 软件 | 能做什么 | 详细说明 |
|---|---|---|
| **MATLAB**（含 Simulink） | 执行脚本与公式计算、搭建和运行 Simulink 仿真、导出图表 | 《[MATLAB 与 Simulink](./matlab.md)》 |
| **STK**（Systems Tool Kit） | 卫星轨道与任务分析：搭场景、批量生成星座、算可见性与全球覆盖、保存场景文件 | 《[STK](./stk.md)》 |
| **Ansys** | 结构仿真（模态 / 静力分析）与电磁仿真（HFSS） | 《[Ansys](./ansys.md)》 |
| **Creo** | 参数化 CAD：读写模型参数与尺寸、重新生成模型、查询质量属性与装配清单、导出模型 | 《[Creo](./creo.md)》 |
| **HyperMesh**（Altair） | 有限元前处理：网格划分、几何清理、材料 / 载荷设置、导出求解器文件，长任务后台执行 | 《[HyperMesh](./hypermesh.md)》 |
| **Nastran**（MSC/NX） | 有限元求解：提交模型跑模态 / 静力 / 屈曲分析，查询长时求解进度 | 《[Nastran](./nastran.md)》 |

> ⚠️ **仅支持 Windows。** 这六款软件的集成功能只在 Windows 系统上可用；在 macOS 或 Linux 上，设置页面里不会出现它们的配置区，Agent 也不具备对应能力。

## 使用前提

- 你的电脑上已经**装好并能正常打开**对应软件本身——3Studio 不包含也不安装这些软件，它只是去连接已经装好的它们；这些软件的许可证同样需要你自己持有，3Studio 不提供。
- 软件未配置或未运行时，该模块的工具不会出现在 Agent 的工具列表里（状态诊断工具除外）；配置完成后新开会话生效。
- 3Studio 会在后台启动一个**桥接程序（Bridge）**来跟这些软件通信，桥接程序依赖一个本地 Python 环境，通常首次使用时会自动准备好，也可以在设置里手动指定（见下一节）。

## Python 环境（通用设置）

打开**设置 → 工具**标签页，各软件卡片之上有一张通用的 **Python 环境** 卡片，用来统一管理这些桥接程序背后依赖的 Python 环境。默认折叠，点标题展开后有两行设置：

- **基座 Python**：默认「自动发现」（3Studio 自动在系统里找一个可用的解释器）；也可以点「选择 python.exe…」手动指定一个版本。指定之后下方会列出各引擎对这个版本的兼容情况——「兼容」或「不兼容（该引擎将回退自动发现）」；想恢复自动发现，点「恢复自动」即可。
- **虚拟环境根目录**：各引擎会在这个目录下各自创建独立的隔离环境（比如 STK 用 `stk-venv`）。默认是应用数据目录，可以点「更改位置…」换到别的磁盘（比如系统盘空间紧张时），点「恢复默认」还原。

> **MATLAB 不受这张卡片影响**：MATLAB 使用它自带的 Python，不参与这里的基座 / 目录设置，也不会出现在兼容性列表里。
> **Nastran 没有手动指定解释器的入口**，它的轻量 Python 环境在后台自动准备；但它**会**出现在这张卡片的兼容性列表里（Nastran 与 Ansys 共用 3.10–3.12 的版本窗口），并且更换基座 / 目录后 Nastran 也会和其他引擎一样在下次启动时重新核查环境，详见《[Nastran](./nastran.md)》。

改动不会立即生效，而是在各引擎**下次启动或重建环境时**才应用；已经就绪的引擎不受影响。如果想立即切换，展开下面对应的引擎卡片（比如 STK 或 Ansys），点「重建隔离环境」按钮——这个按钮随时都在，不需要等出现任何提示。

各引擎对 Python 版本的要求不同（MATLAB 3.9–3.11、STK 3.9–3.13、Ansys 3.10–3.12、Creo 3.9–3.13、HyperMesh 3.9–3.13、Nastran 3.10–3.12），想让所有引擎统一用你指定的基座，选一个都兼容的版本即可（比如 3.11）。

## 侧边栏的「运行时」面板

侧边栏底部有一个独立的「运行时」按钮，点开会展开一个小面板，显示各桥接后台进程当前的运行状态：

- **Bridge**：MATLAB 桥接进程的状态，文案为英文原文（Running / Error / Stopped / Unavailable），不随界面语言切换。
- **Ansys**：Ansys 桥接进程的状态，文案跟随界面语言（中文界面下显示：运行中 / 已停止 / 错误 / 不可用）。
- **Nastran**：Nastran 桥接进程的状态，文案同样跟随界面语言（运行中 / 已停止 / 错误 / 不可用）。
- **STK 与 Creo 没有对应的徽章**——它们的连接状态只能分别在设置页面的 STK / Creo 卡片里查看。

## 连接诊断

打开**设置 → 工具**标签页，Python 环境卡片下方有一张**连接诊断**卡片（仅 Windows 上出现；macOS / Linux 上不渲染）。默认折叠，点标题展开后有一个「开始诊断」按钮。点击后会对六款软件逐一做一次全面体检，体检分四层：

- **软件**：这款软件本身是否安装、路径能否找到
- **环境**：桥接程序依赖的 Python 环境是否就绪
- **桥**：桥接后台进程是否在跑、端口是否连得通
- **端到端**：走一次真实的通信来回，确认真的能对话

每格用符号 + 颜色表示这一层的结果：绿色 `✓` 表示正常；黄色 `◐` 表示部分异常（比如返回了结果但状态是「降级」）；红色 `✗` 表示故障；灰色 `−` 表示这款软件还没配置，或者因为上一层已经失败而跳过了这一层。点任意一格能展开看这一层的详细字段，故障时还会带一句修复建议。

如果某款软件完全没配置，它那一行会先收起显示为「未配置」，点一下才展开成四格详情。

诊断走的是与「测试连接」按钮不同的通信方式（fetch，而不是 http），所以结果面板顶部有一句提示说明这一点——两者结果理论上应该一致，但如果不一致，说明问题出在其中一种通信方式上，值得留意。

诊断完成后，「复制报告」按钮能把结果复制为一段文字（Markdown 格式），方便粘贴给同事或客服支持。诊断结果也会自动包含在右键会话菜单里「导出对话+日志」生成的 zip 包里（一个名为 `connection-diagnosis.json` 的文件），前提是你在导出之前至少运行过一次连接诊断；如果还没跑过诊断就导出，zip 里就不会有这个文件。

## 常见连接问题

以下问题目前能在代码和设置界面里找到依据，遇到其他情况建议直接把「测试连接」返回的错误信息发给 Agent 帮你诊断。

- **MATLAB 卡片显示"未检测到"**：还没有选择 MATLAB 安装目录，去"选择 MATLAB 文件夹…"里重新选一次。
- **提示"无效的 MATLAB 路径"**：选中的文件夹不是一个有效的 MATLAB 安装目录，检查一下路径是否选对了。
- **MATLAB 换了 Python 解释器后好像没生效**：这是预期行为——MATLAB 更换解释器必须**重启应用**才会生效。
- **STK / Ansys 换了「Python 解释器（手动指定）」后好像没生效**：这也是预期行为，但触发方式不同——手动指定的解释器会在该引擎**下次启动或重建环境时**生效；想立即生效，展开对应卡片直接点「重建隔离环境」即可，不用重启整个应用。
- **引擎卡片显示"通用基座 Python 不兼容…已回退自动发现"是什么意思**：说明你在通用「Python 环境」卡片里指定的基座 Python 版本，不在这个引擎的支持范围内，该引擎已经自动回退到自己的自动发现逻辑，不影响正常使用。如果想让这个引擎也统一用你指定的基座，换一个各引擎都兼容的版本即可（比如 3.11）。
- **卡片显示"出错"**：下方会附带具体的错误说明；可以直接点"重试"按钮让 3Studio 重新准备一次（MATLAB / Ansys / STK 也是同样的表现：设置页对应卡片翻成"出错"档，附错误说明和"重试"按钮）。
- **"测试连接"按钮点了但显示失败**：说明桥接程序当前连不上，先确认对应软件本身能正常打开，再确认路径 / 解释器配置无误后重新测试。
- **STK 卡片提示"使用系统 Python（未隔离）"**：说明当前用的解释器不是 STK 专属的隔离环境，展开卡片点"重建隔离环境"让 3Studio 重新搭建一个独立环境（这个按钮平时也一直在，不是只有出现这条提示才有）。
- **桥接连不上，日志里有"is held by a sidecar built from different code"**：端口上已经有一个存活的桥接进程，但它的代码与当前 3Studio 不是同一份，所以 3Studio 拒绝接管，也不会替你结束它。常见诱因是同机跑着两份不同版本的 3Studio，或升级后遗留了旧桥接进程占着端口。解决：在任务管理器里结束对应的 python 进程（或重启电脑）后重试。
  - 症状：六款软件的设置页引擎卡片都会翻成"出错"档并出现"重试"按钮，这是统一的表现；MATLAB / Ansys 另外还有侧边栏"运行时"面板对应徽章同步变化，属于额外补充的旧通道，并非唯一症状。
  - 日志在 `%APPDATA%\3Studio\<引擎名>-bridge\sidecar.log`。
  - 六款软件全部上报代码指纹并接受这项校验（MATLAB、STK、Ansys、Creo、HyperMesh、Nastran），并非只有其中几家。
- **关闭 3Studio 时，已连接的软件会怎样**：3Studio 只会关闭它自己启动起来的那个软件进程——你自己手动打开、3Studio 后来才连上去的实例不会被动，即使正连着 3Studio 也不会被关。判断不出来是不是自己启动的时候，3Studio 一律按"是你的"处理，宁可留一个进程等你手动关，也不会误杀可能有未保存工作的实例。
  - 以 Nastran 为例：求解到一半关闭 3Studio，正常关闭时 3Studio 先把没跑完的任务标记为已取消，再停止桥接进程；停止桥接进程**会**一并终止 3Studio 自己启动的 nastran.exe（设计如此，避免留下杀不掉的孤儿进程）。任务确实没跑完。先取消、后停止这个顺序换来的是**归因**：有这一步，那个任务在重启后会被记成"已取消"；少了这一步，它会被记成"随桥接进程重启而丢失"，并注明它自己的作业目录里有没有留下文件。两种都是明确的失败——3Studio 不会把没跑完的任务当成一次成功恢复的结果交给你。

> ⚠️ 待核对：桥接进程处于 Error / Stopped 状态时，除了"重试"按钮外是否还有其他官方推荐的恢复步骤（例如是否需要重启应用），当前代码里没有找到明确说明，建议后续与研发确认后补充。
